# department-api Specification

## Purpose

Описывает REST-контракт обновления департамента: тело запроса, успешный ответ,
правила валидации и точные коды ошибок, на которые опирается веб-интерфейс
метрологии.

## Requirements

### Requirement: Update department via PUT

Бэкенд SHALL обновлять департамент запросом `PUT /api/v1/departments/{id}` с
телом `{ name, type, parentId? }` и возвращать `200` с обновлённым
`DepartmentResponseDto`.

#### Scenario: Успешное обновление

- **WHEN** запрос содержит существующий `id`, непустое `name`, допустимый `type` и `parentId`
- **THEN** бэкенд сохраняет изменения и возвращает `200` с объектом, содержащим `id`, `name`, `type`, `parent`, `children`, `hasChildren`, `isArchive`, `createAt`, `archiveAt`, `changeAt`

#### Scenario: Обновление без родителя

- **WHEN** в теле запроса `parentId` отсутствует или равен `null`
- **THEN** бэкенд сохраняет департамент без родителя и возвращает `200`

#### Scenario: Тип передаётся всегда

- **WHEN** интерфейс не меняет тип департамента
- **THEN** он всё равно передаёт текущий `type` в теле запроса

### Requirement: Validate name and type on update

Бэкенд SHALL проверять тело обновления до сохранения: `name` обязателен, не пуст
после удаления пробелов по краям и не длиннее 255 символов; `type` обязателен и
должен принадлежать допустимому перечислению.

#### Scenario: Пустое название

- **WHEN** `name` пустое или состоит из пробелов
- **THEN** бэкенд возвращает `400` с сообщением `Название департамента обязательно`

#### Scenario: Слишком длинное название

- **WHEN** `name` длиннее 255 символов
- **THEN** бэкенд возвращает `400` с сообщением `Название не должно превышать 255 символов`

#### Scenario: Некорректный тип

- **WHEN** `type` отсутствует или не входит в перечисление типов департамента
- **THEN** бэкенд возвращает `400` с сообщением `Некорректный тип департамента`

### Requirement: Reject duplicate name via database constraint

Бэкенд SHALL отклонять обновление, если другой департамент уже имеет такое же
название без учёта регистра, и SHALL возвращать `400`, как при создании.
Уникальность SHALL обеспечиваться ограничением БД, без предварительного запроса
существования имени.

#### Scenario: Дубликат названия

- **WHEN** `name` совпадает с названием другого департамента без учёта регистра
- **THEN** бэкенд возвращает `400` с сообщением `Департамент с таким названием уже существует`

#### Scenario: Собственное название не считается дубликатом

- **WHEN** департамент сохраняется с текущим названием без изменений
- **THEN** обновление проходит успешно

#### Scenario: Изменение регистра собственного названия

- **WHEN** департамент сохраняется с тем же названием в другом регистре
- **THEN** обновление проходит успешно

### Requirement: Validate parent on update

Бэкенд SHALL проверять родителя при обновлении: он должен существовать,
не быть самим департаментом, не быть его потомком и не быть архивным.

#### Scenario: Родитель указывает на себя

- **WHEN** `parentId` равен `id` обновляемого департамента
- **THEN** бэкенд возвращает `400` с сообщением `Департамент не может быть родителем самого себя`

#### Scenario: Родитель является потомком

- **WHEN** `parentId` указывает на департамент, вложенный в обновляемый
- **THEN** бэкенд возвращает `409` с сообщением `Нельзя переместить департамент внутрь его дочернего подразделения`

#### Scenario: Родитель не найден

- **WHEN** `parentId` указывает на несуществующий департамент
- **THEN** бэкенд возвращает `404` с сообщением `Родительский департамент с id: {id} не найден`

#### Scenario: Родитель в архиве

- **WHEN** `parentId` указывает на архивный департамент
- **THEN** бэкенд возвращает `409` с сообщением `Родительский департамент удалён`

### Requirement: Validate department state on update

Бэкенд SHALL проверять существование и состояние обновляемого департамента
и SHALL различать отсутствие, архив и прочие нарушения целостности.

#### Scenario: Департамент не найден

- **WHEN** департамент с указанным `id` отсутствует
- **THEN** бэкенд возвращает `404` с сообщением `Департамент с id: {id} не найден`

#### Scenario: Департамент в архиве

- **WHEN** департамент с указанным `id` архивирован
- **THEN** бэкенд возвращает `409` с сообщением `Департамент удалён и не может быть изменён`

#### Scenario: Прочее нарушение целостности

- **WHEN** сохранение отклонено ограничением БД, не связанным с дубликатом названия
- **THEN** бэкенд возвращает `400` с сообщением `Не удалось сохранить департамент`

### Requirement: Update errors use the common format

Ошибки обновления SHALL приходить в формате `{ message, status, timestamp }`.

#### Scenario: Ошибка обновления с сообщением

- **WHEN** бэкенд отклоняет обновление с сообщением о родителе или дубликате
- **THEN** тело ответа содержит `message`, `status` и `timestamp`, а `status` совпадает с HTTP-кодом

#### Scenario: Нечитаемое тело запроса

- **WHEN** тело запроса не является корректным JSON или содержит недопустимый `type`
- **THEN** бэкенд возвращает `400` в формате `{ message, status, timestamp }` с сообщением `Некорректное тело запроса` или `Некорректный тип департамента`
