# Proposal

## Why

Политика D выбрана, чтобы исключить невидимые департаменты: корневой список
каталога строится по типу `FACTORY`, поэтому не-`FACTORY` без родителя не
попадает ни в корень, ни в ветку и становится неуправляемым через UI. Текущий
контракт `PUT` разрешает `parentId = null` для любого типа, а `POST` не требует
родителя для не-`FACTORY`, поэтому такие узлы всё ещё можно создать через API.

## What Changes

- **BREAKING** `POST /api/v1/departments`: для `WORKSHOP`, `AREA` и `LABORATORY`
  поле `parentId` становится обязательным; без него бэкенд возвращает `400` с
  сообщением `Родительский департамент обязателен`.
- **BREAKING** `PUT /api/v1/departments/{id}`: для не-`FACTORY` `parentId`
  обязателен; `null` или отсутствие поля отклоняются с `400` и тем же
  сообщением. Для `FACTORY` очистка родителя остаётся разрешённой, а `FACTORY`
  по-прежнему может иметь родителя и оставаться в корневом списке.
- Durable-спека `department-api` обновляется: правило обязательного родителя
  добавляется для создания и обновления.
- Добавляются тесты на создание и обновление без родителя для каждого типа,
  а также аудит уже существующих записей `type <> 'FACTORY' AND parent_id IS NULL`.
- UI-change `add-department-edit` в `metrology-app-ui` опирается на это правило:
  очистка родителя у не-`FACTORY` запрещена, создание не-`FACTORY` требует
  родителя. Бэкенд выкатывается до UI.

Не входит в change: изменение корневого списка каталога, показ orphan-узлов,
автоматическое перепривязывание существующих записей без родителя, новые
endpoint'ы.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `department-api`: добавляется правило обязательного родителя для не-`FACTORY`
  при создании и обновлении; уточняется сценарий очистки родителя для `FACTORY`.

## Impact

- `src/main/java/.../service/dto/DepartmentDtoService.java` — проверка родителя
  в `save` и `changeById`.
- `src/main/java/.../exception/GlobalExceptionHandler.java` — без нового
  обработчика: используется существующий `IllegalArgumentException` → `400`.
- `src/test/java/...` — тесты создания, обновления и очистки родителя.
- `README.md` — порядок выпуска и правило родителя.
- `metrology-app-ui` — change `add-department-edit` (очистка только для
  `FACTORY`, создание не-`FACTORY` с родителем); выкатить после бэкенда.
- Существующие данные: нужен аудит записей `type <> 'FACTORY' AND parent_id IS NULL`;
  автоматическая миграция не выполняется.
