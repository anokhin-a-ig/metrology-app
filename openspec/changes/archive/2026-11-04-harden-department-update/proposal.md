# Proposal

## Why

`PUT /api/v1/departments/{id}` уже существует, но не защищён: тело не валидируется,
дубликат имени проверяется запросом, который ловит сам обновляемый департамент,
отсутствующий департамент отдаёт `400` вместо `404`, нет запрета циклов и
архивных связей, а очистить родителя через API нельзя. UI-редактирование
департамента (`add-department-edit` в `metrology-app-ui`) опирается на этот
endpoint, поэтому без серверных проверок интерфейс может испортить дерево или
показать неверный статус ошибки.

## What Changes

- `DepartmentRequestDto` получает валидационные аннотации: обязательное непустое
  `name` (до 255 символов) и обязательный `type`; контроллеры создания и
  обновления включают `@Valid`.
- Из `changeById` удаляется предварительная проверка дубликата имени. Уникальность
  обеспечивает существующий регистронезависимый уникальный индекс БД; обновление
  без изменения названия проходит, а конфликт возвращается как `400` с сообщением
  `Департамент с таким названием уже существует`. Чтобы ошибка ограничения
  возникала до завершения транзакции, изменение сохраняется с явным flush.
- Отсутствующий департамент и отсутствующий родитель возвращают `404` через новое
  `DepartmentNotFoundException`; `findById` больше не бросает
  `IllegalArgumentException`. Это меняет `400` на `404` и для создания с
  несуществующим родителем, что соответствует контракту.
- `parentId`, указывающий на сам департамент, отклоняется с `400`; родитель-потомок
  отклоняется с `409`; архивный департамент и архивный родитель отклоняются с
  `409` с отдельными сообщениями.
- `parentId = null` явно очищает родителя: `department.setParent(parent)`
  выполняется всегда, а не только при непустом `parentId`.
- `GlobalExceptionHandler` добавляет обработчики нарушений валидации
  (`MethodArgumentNotValidException`) и нечитаемого тела
  (`HttpMessageNotReadableException`), сохраняя формат
  `{ message, status, timestamp }`.
- Добавляются тесты на валидацию, дубликат (включая неизменное имя), самородителя,
  потомка, архивные записи, `404` и очистку родителя.

Не входит в change: новые endpoint'ы, изменение модели данных, миграции,
изменение поведения UI, пересмотр правил отображения корневого уровня каталога.

## Capabilities

### New Capabilities

- `department-api`: REST-контракт обновления департамента — тело запроса,
  успешный ответ, коды `400`/`404`/`409`, точные сообщения об ошибках и правило
  определения дубликата имени.

### Modified Capabilities

Нет.

## Impact

- `src/main/java/.../dto/request/DepartmentRequestDto.java` — валидационные
  аннотации и русские тексты сообщений.
- `src/main/java/.../rest/DepartmentController.java` — `@Valid` на создании и
  обновлении.
- `src/main/java/.../service/dto/DepartmentDtoService.java` — проверки цикла,
  архива, родителя, явная очистка, отказ от предварительной проверки дубликата,
  flush при сохранении.
- `src/main/java/.../service/DepartmentService.java` — `findById` бросает
  `DepartmentNotFoundException`; при необходимости вспомогательный обход родителей.
- `src/main/java/.../repository/DepartmentRepository.java` — при необходимости
  запрос для проверки потомков или архивности; новых методов для дубликата не
  требуется.
- `src/main/java/.../exception/GlobalExceptionHandler.java`,
  `DepartmentNotFoundException.java`, `DepartmentCycleException.java` — новые
  ответы `400`/`404`/`409`.
- `src/test/java/...` — тесты сервиса и контроллера.
- Парный change `add-department-edit` в `metrology-app-ui`: UI ожидает этот
  контракт. Бэкенд выкатывается первым; без явной очистки родителя сценарий
  «очистить родителя» в UI не даст эффекта.
